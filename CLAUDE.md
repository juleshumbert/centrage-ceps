# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this project is

Weight-and-balance optimisation for parachute-drop aircraft (CEPS Ariege and similar
clubs). Two halves:

1. `heuristique_remplissage/` : the Caravan fixed-seat filling study (heuristics, exhaustive
   enumeration, MILP placement of a real manifest, deliverable binaries). It has its own
   README with the full research narrative; read it before touching the scripts.
2. `avions/` : per-aircraft data extracted from flight manuals (CG envelopes, station arms,
   fuel arms, cabin dimensions) plus the source PDFs, meant to feed centrograms and
   to-scale cabin diagrams for C208, C208B, PC-6 B2-H2 / B2-H4, PAC 750XL, DHC-6.

## Solver, function and web app

- The solver's input/output JSON contract is documented in `solveur/README.md`; the web app
  builds that stick in `web/js/centrage.js` (`stickPourSolveur`) and the function only validates
  and clamps it (`functions/sanitize.js`). Keep the three in sync when adding a field.
- A para "verrou" (lock) is expressed to the solver as `interdit` = every other seat.
- Client-side CG after a drag uses `etapes()` in `web/js/centrage.js`; the test in
  `web/test/centrage.test.mjs` checks it reproduces the solver's published stages on
  `solveur/exemples/exemple_stick.json` to 1e-6. Do not let the two formulas diverge.
- Firebase project `paraclub-planning-f966c` is SHARED with the sibling apps. Deploy only with
  `--only hosting:centrage,functions:centrage`; never a bare `firebase deploy` or `--only functions`.
- CI deploys through Workload Identity Federation (repo variables GCP_WIF_PROVIDER,
  GCP_SERVICE_ACCOUNT, FIREBASE_PROJECT_ID; environment `production`); the SA binding for this
  repo was added on 2026-09-05.
- Cloud Functions gen2 runs on an older glibc than this machine: the binary shipped in
  `functions/bin/` must be built with `PLACEMENT_STATIC=ON` (CI does it; locally reconfigure
  `solveur/build` with that option). On this machine g++ 13 sometimes crashes (internal compiler
  error) at high parallelism: rebuild with `-j 2`.
- The site and the function are PUBLIC (no auth, by decision of the owner). Abuse protection
  lives in `functions/protection.js` (origin check, per-IP limiter, per-instance semaphore, result
  cache) plus `maxInstances`, `concurrency` and the solver time cap in `sanitize.js`. Keep it.
- NO AIRCRAFT REGISTRATION anywhere in the repo, not even in commit messages (history was rewritten
  on 2026-09-05 to remove them). One model per type: `c208b`, `c208a`, `pc6`, `pac750xl`, `dhc6`,
  each with `pesees` (A, B or an estimate). Real manifests (people's names) stay out of git.
- Variants (MTOW + envelope) in `web/js/avions.js` (generated): Caravan `poh`, `ape2` (STC SA00392SE,
  fwd limit 200.23 in at 9062 lb), `ape3` (STC SA01213SE, same envelope, MLW 9000); PC-6 `b2h4`, `b2h2`.
  The club's planches envelope (less restrictive) was deliberately dropped.
- Every aircraft has an `EXT` row outside the fuselage on the door side (paras at the door) and a
  `dessin` schema (fuselage profile to the tail, wing, empennage, blocs). `miseEnPlace()` moves the
  first exit group to the door (2 outside, others inside at the door). PC-6 `porte.moment_ouverture`
  (+21 kg.m, AFM supplement 1824) applies to post-takeoff stages when the door switch is on.
- A para is either on a seat (`place`) or at a free position (`pos:{x,y}` along a row); a lock is
  the seat id or `'libre'` (virtual place `L-<nom>` sent to the solver).

## The notebook dependency

`heuristique_remplissage/caravan_model.py` builds its cabin geometry, fuel table and the
20 fixed seats by `exec`-ing cells 0 to 5 of `reference/notebooks/planche_c208b_A.ipynb`
(`ordre_origine.py` also reads cell 5 of BK and LA). Nothing is copied by hand, so the study
stays consistent with the printed planches. Do not edit those notebooks here: the source of
truth is `../centrage_c208/notebooks/`; refresh by copying the four military notebooks and
updating the commit hash in `reference/notebooks/README.md`.

`ROOT = Path(__file__).resolve().parents[1]` in those two scripts is the repo root.

## Running things

```bash
cd solveur && ./build.sh && ./tests/smoke.sh                 # solver (clones HiGHS v1.9.0 + json.hpp)
npm test --prefix web && npm test --prefix functions          # pure engine + function guards
python3 web/tools/gen_avions.py                               # regenerate web/js/avions.js
cd heuristique_remplissage
python3 placement_milp.py manifestes/exemple_groupes.json      # writes output/placement_exemple_groupes.png
python3 verif_heuristique.py 235
python3 test_placement.py
```

Python deps: numpy, scipy (milp / HiGHS), matplotlib. No virtualenv pinned. Rust binaries
(`enumeration/enumere`, `placement_rs/placement`) build with the musl target and rust-lld.
Compiled binaries, HiGHS sources and build dirs are gitignored.

HTML docs (`doc_placement_milp.html`, `doc_revue_litterature.html`) are turned into PDFs with
`google-chrome --headless=new --print-to-pdf` (no pdflatex or pandoc on this machine).

## Data conventions for `avions/`

- Keep the manual's native units (lb/in for Cessna and DHC-6, kg/m or kg/mm for Pilatus) and
  state them in the JSON. Convert only at display time.
- Envelope vertices are `[weight, arm]` pairs, listed clockwise starting from the forward
  limit at minimum weight; one entry per category or configuration.
- `null` means "not found in a source", never a guess. A value read off a figure carries the
  reading precision in `notes.md`.
- C208B and PC-6 B2-H4 values used by the club planches live in `reference/notebooks/`
  (cell 2 for the Caravan envelope, config cell for EW and moments); when they differ from
  the POH, say which one the planches use.

## Writing style (all documents produced here)

- Never use em-dashes (neither as parenthetical dashes nor as title separators). Use commas,
  parentheses, colons, or « · » in titles and labels. This holds for prose, captions, SVG text
  and strings generated by scripts.
- Parachuting vocabulary: say « para(s) », not « sauteur(s) »; say « mise en place », not
  « mise en porte ».
- French without mandatory accents is accepted in code comments and READMEs of the
  heuristique study (legacy); new prose may use accents.
